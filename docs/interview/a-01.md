**Q: "How do you handle database transactions in NestJS with TypeORM or Prisma?"**

**Your Answer:**
"I use the `@Transaction()` decorator and QueryRunner for complex operations. For example, in the theatre management system, when processing a ticket purchase:

```typescript
async bookTicket(userId: string, eventId: string, seats: string[]) {
  const queryRunner = this.dataSource.createQueryRunner();
  await queryRunner.connect();
  await queryRunner.startTransaction();
  
  try {
    // Lock seats
    await queryRunner.manager.update(Seat, { id: In(seats) }, { locked: true });
    // Create booking
    const booking = await queryRunner.manager.save(Booking, {...});
    // Process payment
    await this.paymentService.charge(userId, amount);
    
    await queryRunner.commitTransaction();
    return booking;
  } catch (err) {
    await queryRunner.rollbackTransaction();
    throw new BookingFailedException();
  } finally {
    await queryRunner.release();
  }
}
```

For simpler cases, I use the `@Transactional()` decorator from typeorm-transactional."

**Q: "Explain Guards, Interceptors, and Pipes in NestJS. When do you use each?"**

**Your Answer:**
"They're part of NestJS's request lifecycle:

- **Guards** (`@UseGuards()`) - Authentication/Authorization, executed before route handlers. I use JwtAuthGuard for protected routes and RoleGuard for role-based access control. In Greenstate, only admin users could access tenant management endpoints.

- **Pipes** (`@UsePipes()`) - Validation and transformation. ValidationPipe with class-validator for DTO validation. In the rental platform, I validated email formats, phone numbers, and price ranges before processing.

- **Interceptors** (`@UseInterceptors()`) - Transform responses, add logging, handle timeouts. I built a LoggingInterceptor that logs request/response timing and a TransformInterceptor to wrap all responses in `{ data, metadata }` format.

**Order:** Guards → Interceptors (before) → Pipes → Controller → Interceptors (after)

I also use **Exception Filters** for centralized error handling - catching all HttpExceptions and formatting them consistently."

## 2. Database Optimization (They emphasize high-performance systems)

**Q: "You worked with Oracle and MSSQL. Tell me about a performance problem you solved."**

**Your Answer:**
"At Egzakta, we had a financial reporting query joining 5 tables (transactions, accounts, users, legal entities, audit logs) that was taking 8-12 seconds for complex date ranges.

**My approach:**
1. **Analyzed execution plan** - found missing indexes and table scans
2. **Added composite indexes** on `(user_id, transaction_date)` and `(account_id, status)`
3. **Optimized JPA queries** - replaced N+1 queries with JOIN FETCH
4. **Added database-level pagination** - OFFSET/LIMIT to avoid loading everything into memory
5. **Implemented Redis caching** for frequently accessed reference data

Result: Query time dropped to 800ms-1.2s.

For MSSQL specifically, I used query hints like `WITH (NOLOCK)` for read-heavy reports where dirty reads were acceptable, and created filtered indexes for commonly queried subsets of data."

---

**Q: "SQL vs NoSQL - when do you choose which?"**

**Your Answer:**
"I choose based on data structure and query patterns:

**SQL (PostgreSQL/MSSQL):**
- Complex relationships and joins - like the theatre system with users, events, seats, bookings
- ACID transactions critical - financial data in Greenstate
- Complex queries with aggregations
- Data integrity with foreign keys

**NoSQL (MongoDB):**
- Flexible schema - the rental platform had varying property types with different attributes
- High write throughput - IoT sensor data in the smart building system
- Document-based data - user profiles with nested preferences
- Horizontal scaling needs

In the delivery platform, we actually used both - PostgreSQL for transactional data (orders, payments) and MongoDB for courier location tracking (high-frequency writes, simple queries)."

**Q: "How do you handle API calls and error handling in Angular?"**

## 6. Domain-Driven Design & Architecture

**Q: "You mention DDD on your CV. How do you apply it in practice?"**

**Your Answer:**
"DDD helps me model complex business logic. At Egzakta, working with legal-financial workflows:

**1. Bounded Contexts:**
- Legal Documents context
- Financial Transactions context
- User Management context
- Each has its own models, even if concepts overlap

**2. Entities vs Value Objects:**
- `LegalCase` is an Entity (has identity, lifecycle)
- `Money` is a Value Object (immutable, no identity)

**3. Aggregates:**
- `LegalCase` aggregate includes `Documents`, `Parties`, `Deadlines`
- Only modify through the aggregate root to maintain consistency

**4. Domain Services:**
- Business logic that doesn't fit in entities
- Example: `CaseAssignmentService` - logic for assigning cases to lawyers

**5. Repository Pattern:**
- Abstract data access
- `LegalCaseRepository` interface, implemented by `TypeOrmLegalCaseRepository`

**Code structure:**
```
src/
  legal-cases/
    domain/
      entities/
      value-objects/
      repositories/
    application/
      use-cases/
      dto/
    infrastructure/
      persistence/
      external-services/
    presentation/
      controllers/
```

This keeps business logic separate from framework code and makes testing easier."

### A) Live coding - API endpoint

**Practice this:**
"Create a NestJS endpoint to create a user with validation"

```typescript
// user.dto.ts
export class CreateUserDto {
  @IsEmail()
  email: string;

  @IsString()
  @MinLength(2)
  name: string;

  @IsEnum(UserRole)
  role: UserRole;
}

// user.controller.ts
@Controller('users')
export class UserController {
  constructor(private readonly userService: UserService) {}

  @Post()
  @UsePipes(new ValidationPipe())
  async create(@Body() createUserDto: CreateUserDto) {
    return this.userService.create(createUserDto);
  }

  @Get(':id')
  async findOne(@Param('id') id: string) {
    const user = await this.userService.findOne(id);
    if (!user) {
      throw new NotFoundException(`User ${id} not found`);
    }
    return user;
  }
}

// user.service.ts
@Injectable()
export class UserService {
  constructor(
    @InjectRepository(User)
    private userRepository: Repository<User>,
  ) {}

  async create(createUserDto: CreateUserDto): Promise<User> {
    const exists = await this.userRepository.findOne({
      where: { email: createUserDto.email },
    });
    
    if (exists) {
      throw new ConflictException('Email already exists');
    }

    const user = this.userRepository.create(createUserDto);
    return this.userRepository.save(user);
  }

  async findOne(id: string): Promise<User | null> {
    return this.userRepository.findOne({ where: { id } });
  }
}
```

### B) SQL Query

**Practice optimizing queries:**

"Find all orders with their customer info and total items, for customers who spent >1000€ last month"

```sql
SELECT 
  c.id,
  c.name,
  o.order_date,
  COUNT(oi.id) as total_items,
  SUM(oi.quantity * oi.price) as order_total
FROM customers c
INNER JOIN orders o ON c.id = o.customer_id
INNER JOIN order_items oi ON o.id = oi.order_id
WHERE o.order_date >= DATE_TRUNC('month', CURRENT_DATE - INTERVAL '1 month')
  AND o.order_date < DATE_TRUNC('month', CURRENT_DATE)
GROUP BY c.id, c.name, o.id, o.order_date
HAVING SUM(oi.quantity * oi.price) > 1000
ORDER BY order_total DESC;
```
