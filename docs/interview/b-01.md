## 1️⃣ Node.js & NestJS – Deep Dive (CORE SECTION)

### 🔹 Questions You WILL Get

### Q1: *Why NestJS instead of plain Express/Fastify?*

**What they’re testing:** architecture thinking, maintainability

**Strong answer**

```text
NestJS enforces structure out of the box — modules, DI, lifecycle hooks.
In larger teams and long-lived systems, this reduces architectural drift.
It also makes testing, scaling teams, and onboarding much easier.
```

**Bonus**

* Built on top of Express/Fastify
* Encourages SOLID
* Declarative patterns (decorators)

---

### Q2: *Explain the NestJS request lifecycle*

**Expected depth**

* Middleware → Guards → Interceptors → Pipes → Controller → Service
* Exception filters at the end

**Key insight**

> Guards are for authorization
> Pipes are for validation & transformation
> Interceptors wrap execution (logging, caching)

---

### Q3: *How do you structure a large NestJS project?*

**Correct approach**

```
src/
 ├── modules/
 │    ├── users/
 │    │    ├── users.controller.ts
 │    │    ├── users.service.ts
 │    │    ├── users.repository.ts
 │    │    └── users.module.ts
 ├── shared/
 ├── infrastructure/
 ├── config/
```

**Say this**

> “Structure follows bounded contexts, not technical layers.”

---

### Q4: *How do you handle cross-cutting concerns?*

| Concern        | Tool         |
| -------------- | ------------ |
| Auth           | Guards       |
| Logging        | Interceptors |
| Validation     | Pipes        |
| Error handling | Filters      |
| Metrics        | Interceptors |

## 2️⃣ Databases – SQL & MongoDB (YOUR POWER ZONE)

### 🔹 SQL Server Questions

### Q5: *How do you debug a slow query?*

**Ideal flow**

1. Execution plan
2. Identify scans vs seeks
3. Missing indexes
4. Check cardinality estimation
5. Reduce data early
6. Verify parameter sniffing

**Say explicitly**

> “I optimize queries based on execution plans, not guesswork.”

---

### Q6: *Indexing strategy?*

* Clustered index on access pattern
* Covering indexes for reports
* Avoid over-indexing
* Composite indexes: order matters

---

### Q7: *OFFSET pagination problem?*

**Correct**

> OFFSET becomes slow for large datasets

**Better**

* Keyset pagination (`WHERE id > last_id`)
* Indexed sort column

---

### 🔹 MongoDB Questions

### Q8: *When MongoDB over SQL?*

**Answer**

* Flexible schemas
* High write throughput
* Aggregations without joins
* Event-like data

**But also say**

> “MongoDB is not a replacement for relational modeling.”

---

### Q9: *Mongo schema design rules*

* Embed when data is always accessed together
* Reference when cardinality is large
* Index on query patterns
* Avoid unbounded arrays

---

### Q10: *Explain DDD in practice*

**Avoid theory dump**

Say:

> “We use DDD where business rules are complex — not everywhere.”

### Q11: *Monolith vs Microservices?*

**Senior answer**

```text
Start with a modular monolith.
Split when:
- Independent scaling is required
- Teams become blocked
- Deployment cycles diverge
```
